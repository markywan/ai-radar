**照抄 1Lookup 做通用的邮箱、手机号验证 API，结论是归档（关 1 不过）；能试的只有一个缩小版：「自带验证服务 key 的外贸开发信名单清洗工具」，最多花 $50、试 7 天，第 7 天没人付钱就停。** 收入证据是真的。我打开了 TrustMRR：1Lookup 的 MRR $254,125，729 个活跃订阅，累计 $5,776,773，近 30 天 $511,702，用 Stripe 验证，2026-11-06 更新。不过它 2022 年 1 月就成立了，页面写着 34 个数据产品共用一个 API key，接了 Twilio、HubSpot、Shopify、Salesforce。它赚钱靠的是四年攒下的集成和大客户，不是验证本身。照抄走不通有四个原因。第一，**批发价已经压到底**：Reoon 的现成额度 $11.90 买 1 万次，每千次约 $1.16；1Lookup 最便宜的套餐每千次 $4.95，ZeroBounce 按量买每千次 $19.50。价差大，但客户买的是信任和集成，新牌子拿不到；Verify Forge 有 $29、$49 两档，累计收入只有 $197，没有活跃订阅，就是证明。第二，**收款平台卡这一类**：Creem 把「API 转售」和「B2B 获客与数据补全软件」列为严格审查，把卖抓来的或买来的邮箱、电话名单列为禁售；Dodo 把「营销与触达工具」列为需审查，「群发、抓取工具」列为禁售。第三，**自建验证引擎很难**：开源的 check-if-email-exists（1.04 万星，MIT）要开出站 25 端口，量一大就要买 SMTP 代理；Hetzner 默认封 25 端口，客户满一个月、付过账单后才能申请解封，批不批看情况。第四，**他没有现成渠道**卖给呼叫中心和美国营销机构。剩下的缝隙是：Franco 这类本地开发信代理要求先配验证 key（Reoon、ZeroBounce、Hunter 三选一），没配就只标 `guess`、一封不发；外贸用户手里的展会名录、海关数据名单很脏，没人专门替他们清洗。所以只卖清洗流程，不卖验证额度。

## 怎么做

做法：不转售任何验证额度。买家填自己的 Reoon 或 ZeroBounce key，额度从买家账户里扣。他卖的是一个本地运行的清洗工具（Python 命令行加 Claude Code Skill），能输出 Franco、Instantly 直接导入的 CSV。

1. **第 1 天：定场景**。只做「外贸 B2B 开发信名单」：展会参展商名录、海关数据导出、LinkedIn 手抄名单（只处理买家自己合法拿到的名单）。先拿自己手上一份 500 条的旧名单当样本。花费 $0。
2. **第 2–3 天：写清洗流程**，用 Claude Code 写，全部用标准库加验证服务 API：
   - 去重，统一大小写，修常见拼写错误（gmial.com 这类）；
   - 标出角色邮箱（info@、sales@）、一次性邮箱、免费邮箱；
   - 查 MX 记录，查域名还在不在用；
   - **按价钱分层调用**：先用买家的 Reoon key 跑一遍（约 $1.16/千次），只有 catch-all（全收型域名）的那一段才建议送去更贵的深度验证。行业里的说法是先用便宜的批量验证，只把 catch-all 送深度验证（见 Modern Inbound 的对比）；
   - 按国家打标签，德国、奥地利、加拿大的地址单独分出来（见合规）；
   - 输出三份：可发、有风险、别发，外加一页英文清洗报告（退信率估计、省了多少额度）。
3. **第 4 天：打包成 Skill**。`list-clean`、`verify-cascade`、`export-franco`、`export-instantly` 四个 Skill，加一个命令行入口。
4. **第 5 天：落地页和收款**。一页英文落地页（Cloudflare Pages），放一份脱敏后的真实清洗报告当样品；接 Creem 卖一次性买断。**上架前先给 Creem 支持发邮件**，说明是本地工具、自带 key、不卖名单、不发信，拿到书面答复再开卖。
5. **第 6–7 天：上线**，去 Franco 的 issue 区和讨论区、冷邮件社区发样例报告（见获客）。

| 项目 | 服务 | 费用 |
|---|---|---|
| 域名 | Cloudflare Registrar | 约 $12/年 |
| 落地页 | Cloudflare Pages | $0 |
| 测试用验证额度 | Reoon 1 万次现成额度 | $11.90 |
| 收款 | Creem（3.9% + $0.40/笔） | 按单扣 |
| AI | 已有 Claude Code 订阅 | $0 |
| 冷启动小推广（可选） | Reddit 推一篇样例报告 | 约 $25 |
| **合计** | | **约 $50** |

不用 VPS：工具在买家电脑上跑，他不经手任何名单数据，也就不用处理隐私和 25 端口的问题。

## 用在哪些场景

- **刚装 Franco 的外贸小团队**：Franco 要求先配验证 key，不知道选哪家、怎么省额度。买这个工具，导入名单，五分钟出一份可发的 CSV，额度花在刀刃上。
- **买了展会名录的工厂业务员**：广交会、Canton Fair 名录里大量 info@ 和已失效域名。先清洗再验证，能少花一半额度（推断，依据是角色邮箱和死域名在验证前就能免费排掉）。
- **海外一人冷邮件代理**：每周给几个客户换名单。用分层验证把每千条成本从 ZeroBounce 的 $19.50 降到 $1–3，报告还能直接发给客户。
- **独立站 B2B 卖家整理老客户邮箱**：复购唤醒前先清一遍，免得退信率太高伤了发信域名。

## 能实现什么

- **产出**：一个 $29 的买断工具（含 Skill 包），一份样例清洗报告，一页英文落地页。
- **30 天目标**：落地页 200–400 个访客，3–8 笔付款（$90–230）。这是推断，依据是一次性数字产品落地页常见的 1–3% 转化率，加上 Franco 仓库 23 天 720 星带来的小众流量。
- **90 天目标**：累计 $300–800。这是推断。说实话这个规模过不了默认关 5 的 MRR $500，更可能是每月一两百美元的小产品；它的价值在于每周 0.5 小时就能养着。
- 对照：通用验证 API 这条路，Verify Forge 有三档定价，累计只有 $197，说明新牌子做「又一个验证 API」，90 天内大概率是 0。

## 未来预测

- **6 个月**：本地开发信代理（Franco 这类）会继续冒出来，它们都把验证外包给第三方 key，名单清洗这个配套需求会跟着长。但验证服务商自己也在补：Truelist 2026 年 6 月上了托管 MCP，EmailVerify.io、EmailListVerify 都有 MCP，免费的「在对话里验证邮箱」很快会成标配。依据：搜到的 MCP 列表。不确定的是 Franco 能不能火过三个月。
- **12 个月**：Gmail、Yahoo 收紧发信规则（投诉率 0.3% 门槛）以后，名单质量越来越要紧，验证需求只会多不会少。但钱会继续流向 ZeroBounce、1Lookup 这些有集成的老牌子，小工具只能吃配套的边角。
- **24 个月**：验证大概率被冷邮件平台内置（Hunter 已经把验证和发信打包进 $49 的套餐）。单独的清洗工具价值会缩水，到时候开源掉或停更。判断依据是 Hunter 的定价结构；这一条不确定性最大。
- **通用验证 API 这条路**：1Lookup 的增长靠四年积累，加上新玩家几乎卖不动（Verify Forge），24 个月内也很难轮到新人，这是推断。

## 风险与对策

1. **收款平台拒绝或冻结**（平台政策风险）：Creem 把 B2B 获客与数据补全软件列为严格审查，Dodo 把营销与触达工具列为需审查、群发和抓取工具列为禁售。对策：上架前书面问 Creem，产品说明里写清「本地运行、自带 key、不提供名单、不发信」；落地页不出现「leads」「scrape」这类词。
2. **验证服务商改接口或改条款**：Reoon 的文档说单条验证接口最多 5 个线程，别拿来做批量。对策：批量一律走它的批量接口；同时适配两家以上，一家变了换另一家；不转售额度，所以不受转售条款约束。
3. **被拿去清洗非法名单**：买家可能拿买来的名单来清洗。对策：使用条款写明只处理买家合法取得的数据；工具不带任何名单、不抓取；德国、奥地利、加拿大的地址默认标成「别发」。
4. **需求太小**：Franco 只有 720 星，可能三个月后就没人用了。对策：同时适配 Instantly、Smartlead 的导入格式，不绑在一个项目上；关 3 过不了直接开源。
5. **免费 MCP 抢走需求**：对策：卖的是外贸名单的清洗规则和分层省钱，不卖「能验证」；如果 30 天内没人为这个差异付钱，就说明差异不值钱，按关 3 处理。

## 合规红线

- **只处理买家合法取得的数据**：能做的是清洗买家自己手上的名单；不能提供、出售、抓取任何名单（Creem 明确禁售抓来的或买来的名单）；做法是使用条款写明，工具不带任何数据源。[Creem 可售产品与审查](https://docs.creem.io/merchant-of-record/account-reviews/account-reviews)
- **发信规则（买家发信时碰到，工具要提醒）**：给 Gmail 每天发 5,000 封以上的发件人要配齐 SPF、DKIM、DMARC，营销邮件要带一键退订，Postmaster 里的投诉率要低于 0.3%（建议 0.1% 以下）。清洗报告里放一节检查清单。[Google 发件人指南](https://support.google.com/a/answer/81126)
- **CAN-SPAM（发美国）**：真实发件人、实体地址、10 个工作日内处理退订。在工具的导出说明里提醒，不替买家发信。[FTC CAN-SPAM 指南](https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business)
- **CASL（发加拿大）**：要先有同意。工具把 .ca 域名和加拿大地址默认分到「别发」。[CRTC CASL 说明](https://crtc.gc.ca/eng/com500/faq500.htm)
- **GDPR（发欧盟）**：B2B 冷邮件靠正当利益，要做平衡测试并留记录；德国、奥地利先不发，工具默认把 .de、.at 分到「别发」。[GDPR 第 6 条](https://gdpr-info.eu/art-6-gdpr/)
- **SMTP 探测**：不在自己的服务器上做 SMTP 探测验证（要开 25 端口，Hetzner 默认封，容易被当成滥用）；验证一律走买家自己的商业验证服务。[Hetzner 云服务器 FAQ](https://docs.hetzner.com/cloud/servers/faq/)
- **开源许可证**：自己的免费版用 MIT；参考的 check-if-email-exists 页面写的是 MIT，可以借鉴，复制代码时保留许可证声明。

## 90 天过关数字

- **关 1（今天）**：已有人在付费（1Lookup 有，验证这个品类有），但他**没有现成渠道**卖通用验证 API，Verify Forge 也证明新牌子卖不动，**原版归档**。缩小版的渠道只有 Franco 仓库和冷邮件社区，算勉强过，所以只给 7 天、$50。
- **关 2（2026-11-14，第 7 天）**：Creem 或 Dodo 书面同意上架，并能收款。否则只发开源版，项目结束，不再投入。
- **关 3（2026-12-07，第 30 天）**：至少 3 笔陌生人付款，落地页转化 3% 以上。默认是 1 笔，这里调高，因为 $29 的一次性产品 1 笔说明不了什么。否则付费版也开源，停止维护。
- **关 4（2027-01-06，第 60 天）**：月收入 $100 以上且在涨，退款加拒付低于 2%。否则冻结，只修严重 bug。
- **关 5（2027-02-05，第 90 天）**：一次性产品没有 MRR，改用**每小时回报 $50 以上**来考核（累计收入 ÷ 累计投入小时数）。否则开源，下线收款。
