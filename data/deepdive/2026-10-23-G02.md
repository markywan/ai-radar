**结论：Firecrawl 值得马上当底层工具用（托管版 $19/月起，或在 VPS 上自托管不花钱），但别拿它去做「网页监控 / 抓取」工具卖钱。这一层已经被挤到 $13/月一档，Firecrawl 自己也推出了 Monitor 功能，同类小产品有人做出过 $7,643 的累计收入，现在却没有在付费的订阅。能试的是窄行业的「抓取 + AI 解读」付费周报。下面按「外贸 B2B 竞品周报」来写：先用 2 周找 10 家工厂测试付费意愿，没人付钱就把这套流程留下，给自己的 SEO 站做数据管道。**

## 怎么做

产品：给有英文独立站的出口工厂做中文竞品周报。每家跟踪 3–5 个海外同行（或国内同行的英文站），每周一早上发一份：竞品新上了什么产品，参数、认证和价格页有没有改，新发了哪些博客或落地页（也就是他们在抢什么关键词），展会和新闻动态，最后附 3 条可以照着做的建议。

| 步骤 | 工具 / 服务 | 花费 | 时间 |
|---|---|---|---|
| 1. 跑通抓取 | Firecrawl 免费档（1,000 积分，并发 2），用 `/map` 拿竞品全站 URL，用 `/scrape` 抓重点页 | $0 | 半天 |
| 2. 变化检测 | `/scrape` 加 `changeTracking` 格式，`git-diff` 模式不额外收费；按 JSON 结构比参数和价格要 5 积分一页 | 计入积分 | 半天 |
| 3. 新页面发现 | 每周跑一次 `/map`（1 积分一次），和上周的 URL 列表做差，就知道新增了哪些页面 | 1 积分/站/周 | 2 小时 |
| 4. 行业动态 | `/search`，每 10 条结果 2 积分，搜「竞品名 + exhibition/certification/launch」 | 很少 | 2 小时 |
| 5. AI 写周报 | Claude API：把 diff 和新页面喂进去，按固定模板写中文周报和建议 | 推断每份 $0.1–0.3 | 1 天写提示词 |
| 6. 发送 | VPS 上用 cron 每周一跑一次脚本，邮件或飞书/企业微信机器人推送 | 见下表 | 半天 |
| 7. 收款 | 国内客户走微信/支付宝收款码或小程序；海外客户走 Stripe 或 Lemon Squeezy | 手续费按笔扣 | 半天 |

积分估算（推断）：每家客户 5 个竞品 × 40 个重点页 × 每周 1 次，约 200 积分/周、870 积分/月。Hobby 档（$19/月，5,000 积分）能撑约 5 家客户，Standard 档（$99/月，10 万积分）能撑约 100 家。超过 Hobby 后也可以改成自托管：Docker Compose 一键起，但自托管版**没有 Fire-engine 反爬能力，截图和页面操作也用不了**，遇到 Cloudflare 防护的站只能走托管版。

**起步成本（第一个月）**

| 项目 | 费用 | 依据 |
|---|---|---|
| Firecrawl Hobby | $19 | 官网定价页 |
| Claude API | $10–20 | 推断，10 家客户、每周 1 份 |
| VPS（2 核 4G，跑 cron 和数据库） | $5–10 | 推断，按常见低价 VPS |
| 域名 + 落地页 | $12 | 推断 |
| 发件服务 | $0–10 | 推断，先用免费档 |
| 样报获客期间多花的抓取积分 | $0（免费档 + Hobby 够用） | — |
| **合计** | **约 $50–70** | 留 $30 余量 |

## 用在哪些场景

1. **做定制型产品的出口工厂老板或外贸经理**（照明、五金、包装、机械配件这类）：海外同行一上新认证（UL、CE）或新系列，他们要能拿去跟客户谈，现在都是业务员不定期上竞品官网看一眼。
2. **SEO 站长或小型外贸建站服务商**：要拿到竞品每周新发的博客和落地页，判断对方在抢哪些关键词，再给自己或客户的站排内容。`/map` 做差正好能出这份清单，这也是日报卡片里提到的 SEO 用法的周更版。
3. **跨境独立站卖家（DTC）**：盯 3–5 个直接竞品的新品、折扣页和首页主推。不过 Shopify 店本身有公开的 `/products.json`，不用 Firecrawl 也能抓到价格，Apify 上已经有一堆现成的 Actor，所以这里只是附带功能，不做主打。
4. **自己用**：给 SEO 站做数据管道（抓行业新闻和政策页，生成内容素材），或者接进现在这个日报仓库，替代一部分 `fetch.py` 的网页解析。这条不赚钱，但即使周报卖不出去，这套代码也不会白写。

## 能实现什么

- **第 1 个月**：做 20 份免费样报，拿到 10 家试用，3–5 家付费。按 ¥199/月算，月收入 ¥600–1,000。这是推断，依据只有一点：同类英文工具卖 $13–70/月还卖不太动（见下文），中文、带解读、行业更窄是这里押的差异点。
- **第 6 个月**：20–40 家付费，月收入约 ¥4,000–8,000，Firecrawl 要升到 Standard（$99）或改成自托管。推断。
- **天花板**：这类产品多是被换掉的。参考 marketminer.ai（电商竞品价格监控）在 TrustMRR 上用 Stripe 核验过的累计收入 $7,643，当前「No active subscriptions」，标价 $49–999/月；PricingMonitor 2025 年 12 月上线，TrustMRR 上收入为空。**纯监控卖不动，客户留不留得住全看解读有没有用。**
- 衡量指标：样报 → 试用转化率 ≥ 30%，试用 → 付费 ≥ 30%，月流失 ≤ 10%。连续两个月不达标就停。

## 客户画像

- **谁付钱**：年出口额几百万到几千万人民币、有独立站和 1–3 名业务员的工厂；决策人是老板或外贸经理。
- **在哪找**：福步外贸论坛，知乎和小红书的外贸话题，外贸 SOHO 和建站服务商的微信群；也可以在阿里巴巴国际站、Made-in-China 上按类目筛出有独立站的供应商。
- **现在怎么解决**：业务员偶尔手动看竞品官网；大公司买海关数据或请咨询公司。英文的通用监控工具有，但只发「某页面变了」的提醒，不说这对生意意味着什么：Visualping $14–70/月（个人档），PageCrawl 年付折合 $13.33–83.25/月，开源的 changedetection.io 可以自己搭。零售大牌用 Particl 这类，第三方页面说 $250–1,000/月，针对美国零售，不适合 B2B 工厂。
- **愿意付多少**：推断 ¥99–399/月。比通用监控工具贵，因为带中文解读；比雇人每周花半天看竞品便宜得多。

## 获客与定价

**第一批 10 个客户**

1. 先从自己做外贸攒下的人脉里找 5 家工厂，每家要 3 个竞品网址，免费出第一期周报。
2. 主动出样报：在 Made-in-China 或国际站上挑 15 家同类目、有独立站的工厂，替他们找出 3 个英文竞品，生成一份真实周报（PDF 或长图），附在私信或开发信里发出去。说「已经帮你看了」，比说「我们能帮你看」更容易被回。
3. 在知乎、小红书发 2–3 篇「XX 行业海外竞品这周在干嘛」的公开拆解（竞品是公开网站，可以写），文末留领取样报的入口。
4. 找 2 家外贸建站服务商谈渠道：周报作为他们给客户的增值服务，按客户数给他们分成 30%。

## 自动化架构

| 环节 | 交给谁 |
|---|---|
| 每周抓取、做 diff、发现新页面、行业搜索 | VPS 上的 cron + Python 脚本调用 Firecrawl（托管 API 或自托管） |
| 判断变化有没有意义 | Firecrawl Monitor 自带的「目标 + 判断」（每个变化页多扣 1 积分），或者自己让 Claude 判断 |
| 写周报、写建议、生成长图 | Claude API，用固定模板 |
| 新客户接入：收竞品网址、生成初始快照 | 表单 + 脚本，自动完成 |
| 写代码、改脚本、修抓取失败 | Claude Code / Codex |
| **还要人做的** | 每周一抽看 3 份周报，看有没有误报和瞎编（约 1 小时）；处理抓取失败的站，比如换托管版或删掉这个竞品（约 0.5 小时）；回复客户、拉新（约 1–1.5 小时） |

稳定后每周约 **2.5–3 小时**。

**AGPL 怎么处理**：用托管 API 不涉及 AGPL。自托管时如果不改 Firecrawl 源码，只在内部用来生成报告、客户拿到的只是周报，一般不触发「对外提供服务要开源」（推断，不是法律意见）。要是改了源码，再让客户直接调用你的接口，就必须公开改动。另外，Firecrawl 服务条款 5.d.3 禁止「转售、分发」其服务本身：可以卖报告，不能把它的 API 包一层转卖。

## 未来预测

- **6 个月**：Firecrawl 继续当 AI 代理抓网页的默认选择。依据：GitHub 约 19.5 万星、1 万多个 fork；2025 年 8 月完成 1,450 万美元 A 轮，创始人称已盈利，Zapier、Shopify、Replit 在用；另有单一来源报道，9 月的 Form D 文件显示新融资约 8,200 万美元，没有核实。它会继续往上做 Agent、Monitor 这类成品功能，**通用的「网页变化提醒」类小工具会更难卖**。
- **12 个月**：反爬越来越严。Cloudflare 2025 年 7 月起对新域名默认拦截 AI 爬虫，并推出 Pay Per Crawl；有第三方站统计约 3% 的头部网站单独屏蔽了 FirecrawlAgent（数据没有核实）。中小工厂官网多数没上 Cloudflare 的高级防护，所以 B2B 竞品监控受的影响比抓媒体站小（推断）。抓取成本可能上涨，定价里要留出空间。
- **24 个月**：通用 AI 代理（ChatGPT、Claude 等的定时任务和深度研究）可能直接替代「每周看竞品」这件事。到那时还能卖的，是积累下来的**历史数据**（竞品一年里改了什么）和行业模板。这一点很不确定，要看通用代理的定时任务做得多好用。

## 风险与对策

1. **平台政策（Firecrawl）**：涨价、改积分规则，或者认定你在转售。对策：报告里只放加工后的结论，不交付原始抓取数据；抓取层用接口隔开，随时能切到自托管、Crawl4AI（Apache 2.0）或 Jina Reader。
2. **平台政策（目标网站和 Cloudflare）**：竞品站上了反爬，或在 robots.txt 里屏蔽 AI 爬虫。对策：每周只抓一次、只抓几十页；遵守 robots.txt；抓不了的竞品如实告诉客户，换别的竞品，不上住宅代理硬抓。
3. **法律和隐私**：日报卡片提到的「抓公司页联系方式做线索表」，碰到欧盟个人邮箱就受 GDPR 约束。Meta 诉 Bright Data 案（2024 年 1 月）只判了「不登录抓公开数据不违反 Meta 条款」，律所提醒不能推广到所有情况。对策：只抓公开的产品、新闻、技术页面，不抓个人信息、不抓登录后的内容；周报里不出现个人联系方式。
4. **付费意愿低**：上面的 TrustMRR 案例说明，纯监控工具留不住人。对策：第 2 周结束前看到 3 家明确愿意付钱再写正式产品；做不到就停，只保留给自己 SEO 站用的数据管道。
5. **AI 解读出错**：把改了 CSS 当成改了价格，或者编造竞品动态。对策：周报里每条结论附原页面链接和 diff 片段；用 Monitor 的「有意义变化」判断过滤噪音；人工每周抽查。
