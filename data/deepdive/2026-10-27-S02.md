**结论：grill-me 本身免费、只是一段提示词，不能拿来卖；值得做的是两件事。第一，马上装上，以后每个新小项目开工前先被它问一轮，这件事不花钱，回报最确定。第二，可以花两周、100 美元以内试一个「垂直领域追问 → 出 brief」的小网页工具（比如外贸开发信方案、独立站产品页文案），但同类产品的收入证据很弱（Proven 累计只赚了 71 美元），要先定好停手条件再动手。**

## 先弄清它是什么

- grill-me 的 SKILL.md 只有一句「调用 `grilling` skill」，真正的规则在 `grilling` 里：把决策排成一棵树，每轮只问前提已经定了的问题，问题编号，每问附推荐答案，用户回「是」就等于接受推荐，然后等用户回答完再问下一轮（[skills.sh/grilling](https://skills.sh/mattpocock/skills/grilling)，99.47 万次安装，过了 Gen Agent Trust Hub、Socket、Snyk 三家安全审计）。
- 它不写任何文件，只能手动输入 `/grill-me` 触发。作者建议：开新会话用，不要叠在已有计划上；**关掉 plan mode**；用最强的模型来追问，实现可以用便宜模型；正常一次大约 4 轮、46 个问题；问到 200 个左右说明范围太大，要拆开；遇到排版、手感这类问不出答案的问题，先做个一次性原型（[官方文档](https://github.com/mattpocock/skills/blob/main/docs/productivity/grill-me.md)）。
- 同仓库配套：`grill-with-docs`（边问边写 `GLOSSARY.md` 和 ADR，留下记录）、`to-spec`（在同一个会话里把追问结果变成需求文档）、`wayfinder`（一次会话装不下的大项目）。仓库 MIT 许可、30.4 万星（[GitHub](https://github.com/mattpocock/skills)）。

对你最有用的组合是：`/grill-me` 问清 → 同一会话 `to-spec` 出需求 → 再交给 Codex/Claude 写。grill-me 没有产出文件，所以你自己用时要在结尾补一句「把定下来的决策整理成 decisions.md」。

## 怎么做

分两条线，A 线今天就做，B 线是可选的赚钱试验。

**A 线：自用（0 美元，半小时）**

1. 装：`npx skills add mattpocock/skills --skill grill-me`，同时装 `grilling`、`to-spec`（Claude Code 也可以 `claude plugin install mattpocock-skills@claude-plugins-official` 装整套）。
2. 在全局 `CLAUDE.md` 里加一句「grill 时一次只问一个问题」（文档里提到的做法），手机上回答更省事。
3. 给自己定规则：任何新小项目、新 SEO 站、新开发信批次，开工前先跑一轮 `/grill-me`，结尾输出 `decisions.md` 放进项目仓库。

**B 线：做一个垂直追问工具「Brief 拷问器」（约 100 美元，2 周）**

思路：通用 PRD 工具已经有 ChatPRD 这样的成熟产品，不去碰；挑一个你熟、对方又常常说不清需求的场景，做成网页：用户回答 3～5 轮追问 → 拿到一份可直接交给写手或 AI 的 brief。首选「外贸开发信 / 独立站产品页 brief」，因为你能判断问题问得好不好。

## 用在哪些场景

1. **你自己开新小项目**：一人养多个项目，最贵的是做了不该做的功能。开工前被追问一轮，MVP 范围先砍一刀。这是确定有用的场景。
2. **外贸业务员 / 小工厂老板准备一批开发信**：他们常常只给一句「我们做 LED，帮我写开发信」。工具逼着他说清目标国家、给哪类买家、拿什么证据（认证、工厂照片、交期），brief 交给 AI 写信时质量差别很大。
3. **接外包的 SEO / 文案自由职业者给新客户做需求收集**：现在多用 Google 表格问卷，问题是固定的，答不到点子上。追问式能根据回答往下问。Gumroad、Payhip、Etsy 上有不少「自由职业者客户入门问卷包」在卖（例如 [Freelancer Client Onboarding Kit](https://pitchpaid.gumroad.com/l/clientonboardingkit)），搜索摘要里的标价大约 5～19 美元，但我打开的页面没显示价格和销量，这个区间未核实。
4. **独立开发者写落地页文案前**：先被问清楚目标用户、替代方案、为什么现在买，再让 AI 写。
5. **自媒体选题策划**：一个模糊选题，被问到能写出大纲为止，再批量生成。

## 能实现什么

- **A 线（自用）**：可衡量的目标是「每个新项目从想法到第一版上线的返工次数」。没有公开数据，推断：每个项目少做 1～2 个没人用的功能，省下的时间比装这个 skill 的成本高得多。
- **B 线（工具）**：保守目标，上线 8 周内 200 次免费试用、10 个付费用户、月收入 100～300 美元（推断）。依据：
  - 同类最成功的 ChatPRD：2023 年底从一个 GPT 起步，2025-06 有 5 万用户、50 万次以上对话（[ChatPRD 博客](https://www.chatprd.ai/blog/claire-full-time-on-chatprd)），据搜索摘要，官网现称 10 万以上产品经理在用、2024 年 12 月 Every 的报道称它是「六位数的副业」（这两处原页面我没打开）；没有公开 ARR。它有创始人在产品圈的大量粉丝，你没有，不能照搬。
  - 同类小产品 Proven（想法验证工具，按次 9 美元起）：TrustMRR 上 Stripe 验证的累计收入只有 **71 美元**、当前无订阅、约 120 用户（[TrustMRR](https://trustmrr.com/startup/proven)，2026-10-26 更新）。这说明「通用的、面向独立开发者的问答式工具」很难卖。
  - 所以要做就做垂直的、面向会花钱办事的人（外贸工厂、接单的自由职业者），而不是面向同样会用 Claude 的独立开发者——后者自己装个免费 skill 就行。

## 获客与定价

**第一批 10 个客户：**

1. 你自己认识的外贸朋友先免费用 3 个，换真实的 brief 案例和一句评价（第 1 周）。
2. 把「改前 / 改后」开发信对比发到小红书和福步论坛：同一个产品，一句话需求写出来的信 vs 被追问 5 分钟后写出来的信。案例本身就是广告（第 2 周起，每周 2 篇）。
3. 开源一个免费的 SKILL.md 版本（`foreign-trade-grill`），README 里放网页版链接。会用 Claude Code 的人自己用，不会的去网页付费。skills.sh 有现成的流量，grilling 一个 skill 就有近百万安装。
4. 在 3 个外贸社群里做一次「免费帮 10 个人追问一遍开发信方案」，留下愿意付钱的。
5. 写 3 篇 SEO 文章：「外贸开发信怎么写才有回复」「开发信要准备哪些素材」「AI 写开发信为什么像模板」，每篇嵌入工具。

**定价：**

- 免费：每天 1 次，只给 brief 不给最终信件。
- 单次 19 元人民币 / 3 美元：完整 brief + 3 封不同角度的开发信草稿。
- 月付 49 元人民币 / 9 美元：不限次数、保存历史 brief、可导出。
- 不做定制、不做一对一咨询，遇到要人帮忙的直接拒绝或只给文档。

## 自动化架构

| 环节 | 谁做 |
|---|---|
| 追问逻辑、问题树迭代 | Claude Code 改提示词；每周跑一次脚本，把上周用户中途放弃的那一轮挑出来给 Claude 分析该删哪些问题 |
| 线上追问会话 | VPS 或 Cloudflare Worker 调 Anthropic API（Sonnet 追问够用；作者建议追问用强模型，付费版可换更强的） |
| 付款、开通 | Lemon Squeezy / Stripe Webhook 自动开通 |
| 小红书、SEO 文章初稿 | Claude 批量写，你每周挑 2 篇改完发 |
| 用户数据周报 | VPS 定时任务，每周一把试用数、付费数、放弃率推到飞书 |
| 仍要人做 | 判断问题树问得对不对（这是产品的核心，不能全交 AI）、发帖、回复社群消息 |

稳定后每周人工约 2～3 小时：1 小时改提示词，1 小时发内容，半小时看数据。

## 未来预测

- **6 个月**：「先问清再动手」会成为编程代理的标配。依据：grill-me 3 月上线、底层 grilling 6 月上线，现在分别 140 万和近百万安装；Claude Code 的 plan mode、Kiro 的 spec 流程都在往这个方向走。后果是**通用追问工具会被免费的内置功能吃掉**，只剩垂直场景有付费空间。
- **12 个月**：通用 AI 助手大概率会内置「澄清问题」能力，外贸人用的豆包、ChatGPT 也会主动追问。垂直工具的护城河只剩两样：行业决策树（你懂外贸）和积累下来的案例。不确定的是外贸人是否愿意为「问问题」单独付钱，很可能要和写信、找客户这些结果打包卖。
- **24 个月**：判断不了这个单品还能不能独立存在。更现实的走向是把追问能力变成你其他外贸 / SEO 产品的开头一步，而不是单独卖。

## 风险与对策

1. **平台政策：不能拿订阅令牌做产品。** Anthropic 2026 年 2 月更新的法律与合规页写明，Free / Pro / Max 的 OAuth 令牌只能用在 Claude Code 和 Claude.ai，做产品（包括用 Agent SDK）必须用 Console 的 API key，1 月已开始在服务端拦截（[AlternativeTo 报道](https://alternativeto.net/news/2026/2/anthropic-officially-bans-using-subscription-authentication-for-third-party-claude-use)）。对策：线上工具一律用 API key，按量计费；自用继续用订阅。
2. **没人买（最大风险）。** Proven 累计 71 美元就是例子。对策：开发前先在社群里卖 10 份「人工 + AI」的预售，卖不到 3 份就只保留 A 线自用。上线 8 周付费用户少于 5 个就停，不再投入时间。
3. **用户嫌问题多，中途放弃。** 文档说正常一次 46 个问题，外贸业务员不会有这个耐心。对策：垂直版限制在 3 轮、15 个问题以内，每问给推荐答案让用户点「是」；记录每轮放弃率，每周删问题。
4. **免费 skill 被复制。** MIT 许可、提示词公开，谁都能抄。对策：开源的只是引流版，付费版的价值放在行业问题树、案例库和导出格式上；别指望靠卖文件赚钱（[Agent37](https://www.agent37.com/blog/monetize-claude-code-skills) 把卖文件列为最弱的方式，因为买走就能复制转发；它自己卖托管服务，有立场）。
5. **小红书对引流和广告的限制。** 笔记里直接放链接、二维码容易被限流。对策：笔记只放改前改后案例，引导搜索工具名或进主页；主要转化放在 SEO 文章和 GitHub。

- [ ] 周日：把垂直版 SKILL.md 开源到 GitHub，写第一篇改前改后对比笔记，定下 8 周停手线（付费少于 5 个就停）。
