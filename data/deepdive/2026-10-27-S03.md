**值得装，但定位要对：把 last30days 当成你各个项目共用的「近 30 天舆情素材引擎」，在它上面做一份垂直领域的免费周报 + 程序化 SEO 页面，靠赞助和导流变现；不要把它包装成「Reddit 数据报告」直接卖钱。** 同类产品 GummySearch（14 万用户）2025-11-30 因拿不到 Reddit 商用授权宣布关停，Reddit Data API 条款要求商用另签协议、转售或靠它收费要书面批准，卖数据这条路已经有人走死了。卖的应该是你的判断和整理，原始讨论只当引用来源。

## 怎么做

整体思路：选一个你熟、有人愿意付钱的垂直方向（例：「跨境卖家的 AI 工具」「独立开发者的 SaaS 定价」「某类 B2B 工具的用户抱怨」），VPS 上每周定时跑 last30days，Claude Code 把多份简报合成一期周报和若干 SEO 页面。

### 第 1 步：本地装好、摸清边界（第 1 天，0 美元）

- 安装：Claude Code 里 `/plugin marketplace add mvanhorn/last30days-skill`，或 `npx skills add mvanhorn/last30days-skill -g`。引擎是 `scripts/last30days.py`，**要 Python 3.12+ 和 node**。
- 先跑 `--preflight`，它只展示配置、cookie 计划和写入位置，不真的去抓，也不读 cookie 值。
- 安装时问要不要读浏览器 cookie，一律拒绝；不设 `FROM_BROWSER`、`AUTH_TOKEN`、`CT0`。X 要用就走 `X_BEARER_TOKEN`，或者干脆不用。
- 输出默认写到 `~/Documents/Last30Days`（`LAST30DAYS_MEMORY_DIR` 可改），在 VPS 上改到项目目录。
- 用你的 3 个候选方向各跑一次，记下每次耗时和各来源返回多少条。README 没写一次要跑多久，只说 Reddit 默认深度每次补抓约 10 次 API 调用，所以耗时要自己测。

### 第 2 步：决定开哪些来源（第 2 天，0～47 美元）

| 来源 | 要什么 | 费用（页面所写） |
|---|---|---|
| Reddit、HN、Polymarket、GitHub、arXiv、Techmeme、DEV | 不用密钥 | 免费 |
| YouTube | 装 `yt-dlp` | 免费 |
| TikTok、Instagram、Threads、LinkedIn、YouTube 评论 | `SCRAPECREATORS_API_KEY` | 免费 100 次，填反馈后最多再领 7000 次；之后 $47 买 2.5 万次（每千次 $1.88） |
| 网页搜索 | `BRAVE_API_KEY` | 每月 2000 次免费 |
| X | `X_BEARER_TOKEN` 或 xAI 等 | 按 X 开发者额度另算 |
| 重排、推理 | OpenAI/xAI/OpenRouter/Gemini 任一 | 可不填，不填时用本地打分模型 |

建议先只开免密钥来源 + Brave，跑两周后再看要不要买 ScrapeCreators。

### 第 3 步：VPS 定时任务（第 3～4 天）

- cron 每周一凌晨跑：对 5～10 个固定话题各跑一次 `--emit=json --output <文件>`，再跑一次 `--discover` 找新话题。
- 加 `--store`（SQLite），保存历史，方便周与周之间比较「哪些说法在变多」。
- 跑完调 Claude Code（headless 模式）读这批 JSON，按固定模板写成：1 期周报草稿 + 3～5 个 SEO 页面草稿（「X 工具 2026 年 11 月用户评价汇总」「A vs B：社区怎么说」，用它自带的对比模式 `--competitors`）。
- 每次运行先跑 `doctor --cached --json`，有来源坏了就推一条飞书提醒。

### 第 4 步：发布渠道（第 5～6 天）

- 周报：beehiiv 免费版（2500 订阅以内免费，但**免费版不能开付费订阅，也不能进广告网络**，要等升级到 Lite，月付 $59 起）。
- SEO 页面：静态站（Cloudflare Pages / GitHub Pages）+ 一个域名。

## 用在哪些场景

1. **你自己的自媒体选题**：每周一跑 5 个关注话题，拿到互动最高的讨论和原话，直接当选题池；比刷 X、Reddit 省 2～3 小时（推断）。
2. **外贸开发信**：对目标品类跑「<产品> complaints / problems」，拿到买家近一个月的真实抱怨，开发信第一句就引用痛点。适合做 B2B 小品类、客户在 Reddit 和 YouTube 评论区活跃的卖家。
3. **做产品前的验证**：给一个新点子跑 `--competitors`，看竞品用户最近骂什么、在哪个子版块骂，决定做不做、先做哪个功能。适合你「同时养很多小项目」的节奏，每个点子 10 分钟出结论。
4. **SEO 内容**：「<工具> 评价」「A vs B」这类带月份的搜索词，用近 30 天社区原话写，比 AI 套话页面有信息量，也天然每月可更新。
5. **周报读者**：给某个垂直圈子（比如用 AI 工具的独立站卖家）每周省下刷论坛的时间。

## 未来预测

- **6 个月**：仓库已有 6.56 万星、5.7k fork、1418 次提交，版本到 v3.31.0，更新很快，会继续加来源（已有小红书、Telegram、Amazon）。同类免费 Skill 会更多，「会用 last30days」本身不再是稀缺能力。**判断**：工具层面越来越强，护城河只能是你选的方向和观点。
- **12 个月**：Reddit 对数据访问持续收紧（第三方文章称现在申请 API 访问也要审批，商用另签协议）。GummySearch 的结局说明，规模化、收费地用 Reddit 数据风险最高。**判断**：last30days 的 Reddit 免密钥路径可能变得不稳，要准备只靠 HN、YouTube、GitHub、X 也能出周报。这点不确定，取决于 Reddit 是否对个人非商用访问动手。
- **24 个月**：Perplexity、ChatGPT 等通用搜索会把「近 30 天社区观点」做成默认功能。**判断**：通用工具会吃掉「快速查一下」的需求，留下来的是有固定读者、长期追踪一个垂直领域的周报。现在就积累订阅和历史数据库（`--store`）是对冲。

## 风险与对策

1. **平台政策（Reddit）**：Reddit Data API 条款要求商用另签协议，靠它收费要书面批准；GummySearch 因此关停。对策：不卖原始数据和导出；周报里只做短引用 + 链接回原帖 + 自己的分析；收入来自赞助和观点，不来自「数据访问」；多来源混合，Reddit 不占主导。
2. **X、TikTok 等平台抓取风险**：用 cookie 登录抓 X 可能导致账号被封，ScrapeCreators 这类第三方抓取也处在灰色地带。对策：不读浏览器 cookie；X 只用官方 Bearer Token 或不用；短视频平台按需开。
3. **本地安全**：Skill 会跑本地脚本、写文件、持有多个密钥。对策：在单独的 VPS 用户或容器里跑；密钥只放这个环境；每次升级先看 diff；README 明确说没有 pro 版，别装 npm 上的仿冒包和镜像站版本。
4. **内容同质化**：谁都能装这个 Skill，AI 合成的周报很快泛滥。对策：选窄方向、每期写自己的判断；用 SQLite 历史做「本月 vs 上月」趋势对比，这是一次性查询给不了的。
5. **SEO 风险**：批量 AI 页面可能被 Google 判为低质内容。对策：每页必须有真实引用和日期；控制数量，每周 3～5 页，不要一次铺几百页。
