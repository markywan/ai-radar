# 深挖说明（给 Claude）

用户在日报里点了「收藏并深挖」。收藏条目在 `data/favorites/<编号>.json` 的 `item` 字段里，`type` 说明它来自哪个栏目（opportunities / tools / skills / news / trends）。

读者是一位一人公司创业者：做过外贸、SEO、自媒体；用 Claude Code / Codex、VPS 和各种 API 把事情自动化；想同时养很多个小项目，每个起步资金 100 美元左右（最多 500），稳定后每周人工不超过 3 小时；不做需要大量私人定制或耗时咨询的业务。2026-10-26 起他的方向是一个人做海外生意（全球贸易、SEO 与 GEO、图文自媒体、供需撮合、海外宣传），用大陆个人身份收海外的钱，暂不注册公司。

用 WebSearch / WebFetch 认真研究，然后把分析写到 `data/deepdive/<编号>.md`。全文中文，用 Markdown（只用 `##` / `###` 标题、列表、表格、粗体、链接）。

## 必须包含的部分

1. **一句话结论**：值不值得做，为什么。放在最前面，不加标题。
2. `## 怎么做`：从零到上线的分步骤方案，每一步写清用什么工具或服务、花多少钱、多久。起步资金控制在 100 美元左右，列一张成本表。
3. `## 用在哪些场景`：具体到人群和情境，至少 3 个。
4. `## 能实现什么`：上线后的产出和可衡量的目标（流量、订阅数、收入区间），说明依据。
5. `## 客户画像`：谁会付钱、在哪里能找到他们、他们现在怎么解决这个问题、愿意付多少。
6. `## 获客与定价`：第一批 10 个客户怎么来；定价方案。
7. `## 自动化架构`：哪些交给 Claude / Codex、哪些交给 VPS 上的定时任务或开源项目、哪些仍要人做，稳定后每周几小时。
8. `## 未来预测`：6、12、24 个月的走势判断，写清依据（趋势数据、同类产品轨迹、平台政策）。判断不确定的地方直说。
9. `## 风险与对策`：至少 3 条，含平台政策风险。
10. `## 第一周行动清单`：每天做什么，用 `- [ ]` 列出。
11. `## 怎么收钱`：他用大陆个人身份能不能收到这笔钱。默认方案是代收平台（Merchant of Record，替他当卖家、代缴各国增值税和销售税）：先用 [Creem](https://www.creem.io/pricing)（3.9% + $0.40）或 [Dodo Payments](https://dodopayments.com/pricing)（美国卡 4% + $0.40，非美国卡再加 1.5%），两家都支持大陆个人；回款进万里汇，提现人民币 0.7% 封顶。Stripe 不收大陆商户，Lemon Squeezy 新项目别用。写清这个项目的卖法（订阅、一次性、按量）平台支不支持，平台的禁售或限售清单里有没有这一类（数据抓取、营销邮件、联盟类常被卡）。以上费率是 2026-10 的，写之前打开定价页和禁售清单核对，附链接。
12. `## 合规红线`：只写这个项目碰得到的，每条写「能做什么、不能做什么、怎么做才行」，附规则原文链接。常见的：给 Gmail、Yahoo 发信要配齐 SPF、DKIM、DMARC，带一键退订，投诉率低于 0.3%；发美国守 CAN-SPAM（真实发件人、实体地址、10 个工作日内退订）；发加拿大守 CASL，要先有同意；发欧盟按 GDPR 的正当利益要做平衡测试、留记录，德国、奥地利先不发；LinkedIn 不用自动化插件加人、发消息、抓数据；WhatsApp 只发给明确同意过的号码，不用非官方工具群发；抓数据先看网站条款和 robots.txt；拿开源项目做托管版先看许可证档位（AGPL 托管要公开改动，BUSL、Elastic、SSPL 这类不能托管来卖）。
13. `## 90 天过关数字`：按五道关写这个项目的具体数字和日期，过不了就按「否则」处理，不拖着。默认数字：关 1（深挖完）已有人在付费，且他有现成渠道，否则归档；关 2（第 7 天）能收款，否则砍到只剩一个功能；关 3（第 30 天）至少 1 笔陌生人付款，转化 3% 以上或回复 5% 以上，否则砍掉或换渠道；关 4（第 60 天）月收入 100 美元以上且在涨，退款加拒付低于 2%，否则冻结；关 5（第 90 天）MRR 500 美元以上，或每小时回报 50 美元以上，否则卖掉、开源或下线。数字可以按这个项目调，调了写原因。
14. `## 参考来源`：你打开过的页面链接。

如果收藏的是工具或 Skill，把重点放在「怎么用它做一个能赚钱的小项目」，同样按上面的结构写。先看许可证档位能不能做托管版来卖；再打开它的 issue 区按点赞排序（`https://github.com/<仓库>/issues?q=is%3Aissue+is%3Aopen+sort%3Areactions-%2B1-desc`），用户最想要、维护者还没做的东西，就是插件、Skill、教程或托管版的切入点，写进 `## 客户画像` 和 `## 获客与定价`。

如果收藏的是玩法风向（trends），先打开 `evidence` 里的帖子链接核对数字，再去同一平台和其他平台找更多同类内容，判断这股风还能刮多久；重点写清楚怎么用 AI 批量做出同类内容或产品、第一批账号或产品怎么起步、平台对 AI 生成内容和矩阵号的规则。

## 质量红线

- 收入、价格、搜索量等数字只写你在页面上看到的，并附链接；没有数据的写「推断」。
- 不要写空话，不要重复日报卡片里已有的话。
- 只写 `data/deepdive/<编号>.md` 这一个文件。
