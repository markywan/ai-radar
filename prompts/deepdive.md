# 深挖说明（给 Claude）

两种情况会叫你来深挖：
- **每天自动深挖今日机会**：日报里的今日机会打了 75 分以上、池子里又没有「验证中」的项目时，日报写好后自动深挖。条目在 `data/daily/<日期>.json` 的 `opportunities` 里（`hypothesis` 是窄假设，`gates` 是 7 条门槛，`score` 是 100 分打分，`evidence` 是证据链接）。
- **用户在日报里点了「收藏并深挖」**：条目在 `data/favorites/<编号>.json` 的 `item` 字段里，`type` 说明它来自哪个栏目（opportunities / tools / skills，老日报里还有 news / trends）。

读者是一位一人公司创业者：做过外贸、SEO、自媒体；用 Claude Code / Codex、VPS 和各种 API 把事情自动化；想同时养很多个小项目，每个起步资金 100 美元左右（最多 500），稳定后每周人工不超过 3 小时；不做需要大量私人定制或耗时咨询的业务。方向是一个人做海外生意（全球贸易、SEO 与 GEO、图文自媒体、供需撮合、海外宣传），用大陆个人身份收海外的钱，暂不注册公司。

**2026-11-26 起深挖机会不再写「这个生意怎么样」的长报告，而是写一份能马上动手的验证设计**：选哪个窄切口、最可能错的假设是什么、第一批 10 个客户在哪、7 天花多少钱试什么、第 7 天看哪个数、什么情况停。以前 6 篇深挖都是「照抄不做，收窄到外贸版」，收窄这一步现在就是深挖的主体。

用 WebSearch / WebFetch 认真研究，然后写到 `data/deepdive/<编号>.md`。全文中文，用 Markdown（只用 `##` / `###` 标题、列表、表格、粗体、链接），控制在 4000 字以内。

## 深挖机会：必须包含的部分

1. **一句话结论**：做还是不做，做的话做哪个切口、先花多少钱试几天。放在最前面，不加标题。
2. `## 先核实`：逐条打开卡片里 `evidence` 和 `source` 的链接，数字对不上、页面打不开、其实是视频生意或一个人做不了的直说。核实不过就结论写「不做」，后面只写「## 参考来源」和「## 池子卡片」。
3. `## 三个窄切口`：围绕卡片的假设，列 2–3 个更窄的切法（换客户、换交付物、换渠道），一张表比较：客户、交付物、价格、第一批客户从哪来、7 条门槛过不过、按日报的 100 分标准各打几分。选一个，写为什么。
4. `## 最可能错的假设`：选定的切口里，哪一个假设错了整件事就不成立（多半是「他们真的会付这个价」或「这个渠道真的触达得到」），怎么用最少的钱最快证伪。
5. `## 第一批 10 个客户`：具体到哪个群、哪个目录、哪个论坛帖、哪类 LinkedIn 搜索条件，第一条消息怎么写（给一段可以直接发的中文或英文），合规地联系（不群发私信、不用自动化插件加人）。
6. `## 样品和报价`：先做什么样品给他们看（一页报告、一个演示、一个免费版），报价怎么写，收款链接用什么。
7. `## 7 天实验`：表格写第 1–7 天每天做什么、花多少钱（总共不超过 100 美元）；最后写清**第 7 天看哪个数**（比如「10 个人里有 2 个回复问价格」「拿到 1 笔 $29」）和**停止条件**（过不了就淘汰还是换渠道）。
8. `## 自动化架构`：稳定后哪些交给 Claude / Codex、VPS 定时任务或开源项目（可以点名日报里出现过的 GitHub 工具和 Skills），哪些仍要人做，每周几小时。一段话加一张表，不展开。
9. `## 怎么收钱`：他用大陆个人身份能不能收到这笔钱。默认方案是代收平台（Merchant of Record，替他当卖家、代缴各国增值税和销售税）：先用 [Creem](https://www.creem.io/pricing)（3.9% + $0.40）或 [Dodo Payments](https://dodopayments.com/pricing)（美国卡 4% + $0.40，非美国卡再加 1.5%），两家都支持大陆个人；回款进万里汇，提现人民币 0.7% 封顶。Stripe 不收大陆商户，Lemon Squeezy 新项目别用。写清这个项目的卖法（订阅、一次性、按量）平台支不支持，平台的禁售或限售清单里有没有这一类（数据抓取、营销邮件、联盟类常被卡）。以上费率是 2026-10 的，写之前打开定价页和禁售清单核对，附链接。
10. `## 合规红线`：只写这个项目碰得到的，每条写「能做什么、不能做什么、怎么做才行」，附规则原文链接。常见的：给 Gmail、Yahoo 发信要配齐 SPF、DKIM、DMARC，带一键退订，投诉率低于 0.3%；发美国守 CAN-SPAM（真实发件人、实体地址、10 个工作日内退订）；发加拿大守 CASL，要先有同意；发欧盟按 GDPR 的正当利益要做平衡测试、留记录，德国、奥地利先不发；LinkedIn 不用自动化插件加人、发消息、抓数据；WhatsApp 只发给明确同意过的号码，不用非官方工具群发；抓数据先看网站条款和 robots.txt；拿开源项目做托管版先看许可证档位（AGPL 托管要公开改动，BUSL、Elastic、SSPL 这类不能托管来卖）。
11. `## 90 天过关数字`：按五道关写这个项目的具体数字和日期，过不了就按「否则」处理，不拖着。默认数字：关 1（深挖完）已有人在付费，且他有现成渠道，否则归档；关 2（第 7 天）能收款，否则砍到只剩一个功能；关 3（第 30 天）至少 1 笔陌生人付款，转化 3% 以上或回复 5% 以上，否则砍掉或换渠道；关 4（第 60 天）月收入 100 美元以上且在涨，退款加拒付低于 2%，否则冻结；关 5（第 90 天）MRR 500 美元以上，或每小时回报 50 美元以上，否则卖掉、开源或下线。数字可以按这个项目调，调了写原因。
12. `## 走势判断`：3–5 句，这个切口 6–12 个月会变好还是变差（平台政策、大厂免费工具、价格战），依据写链接，不确定的直说。
13. `## 参考来源`：你打开过的页面链接。
14. `## 池子卡片`：最后一段，一个 ```json 代码块，脚本会把它写回机会池（`data/opportunities/`）。格式：

```json
{"verdict": "做|不做", "chosen_cut": "选定的窄切口名字（30 字以内）", "reason": "一句话为什么",
 "hypothesis": {"customer": "", "pain": "", "deliverable": "", "price": "", "channel": ""},
 "riskiest_assumption": "", "next_action": "他明天就能做的第一步，一句话",
 "due_in_days": 7, "experiment_metric": "第 7 天看哪个数、多少算过", "stop_condition": "什么情况直接停"}
```

仓库是公开的，池子卡片和报告里不写具体客户的名字、邮箱、电话。

## 深挖工具、Skill 和老栏目

如果收藏的是工具或 Skill，先看许可证档位能不能做托管版来卖；再打开它的 issue 区按点赞排序（`https://github.com/<仓库>/issues?q=is%3Aissue+is%3Aopen+sort%3Areactions-%2B1-desc`），用户最想要、维护者还没做的东西，就是插件、Skill、教程或托管版的切入点，写进 `## 客户画像` 和 `## 获客与定价`。

如果收藏的是玩法风向（trends），先打开 `evidence` 里的帖子链接核对数字，再去同一平台和其他平台找更多同类内容，判断这股风还能刮多久；重点写清楚怎么用 AI 批量做出同类内容或产品、第一批账号或产品怎么起步、平台对 AI 生成内容和矩阵号的规则。

这类深挖按「怎么用它做一个能赚钱的小项目」写：一句话结论、`## 怎么做`（步骤和成本表）、`## 客户画像`、`## 获客与定价`、`## 自动化架构`、`## 风险与对策`、`## 怎么收钱`、`## 合规红线`、`## 参考来源`，要求同上，不写池子卡片。

## 质量红线

- 收入、价格、搜索量等数字只写你在页面上看到的，并附链接；没有数据的写「推断」。
- 不要写空话，不要重复日报卡片里已有的话。
- 只写 `data/deepdive/<编号>.md` 这一个文件。
