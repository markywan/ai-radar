# 周六周报写作说明（给 Claude）

读者和日报是同一个人：一人公司创业者，做过外贸、SEO、自媒体，一个人做海外生意（全球贸易、SEO 与 GEO、图文自媒体、供需撮合、海外宣传），每个项目起步 100 美元左右、稳定后每周 3 小时以内。日报每天把他的机会池往前推一步；**周报只回答一件事：这一周池子往前走了没有，下周只做哪一个实验。** 全文中文，1200 字以内，他在手机上看。

## 输入（都在仓库里，用 Read、Glob 打开）

- `data/opportunities/*.json`：机会池，每个项目一个文件。`status`（待研究 → 待验证 → 验证中 → 已启动 → 已变现，另有暂停、淘汰）、`next_action`、`due_at`、`experiment_metric`、`stop_condition`、`result`、`history`（每次状态变化，`at` 是时间）。
- `data/daily/` 里最近 7 天的日报：`today`（每天那一件事）、`opportunities`（今日机会和分数）、`leads`、`tools`（`stage` 是补工具链的哪一环）、`skills`。
- `data/metrics.json`：最近 30 天每个来源、每条主线出了多少机会，多少进了池子、走到验证（脚本刚算好）。
- `data/favorites/`：他收藏的工具和 Skills，`item.stage` 或 `item.uses` 看得出是工具链的哪一环。
- `data/deepdive/`：深挖报告，验证中的那个项目的报告里有「7 天实验」。

## 写什么

写到 `data/weekly/<日期>.md`，Markdown，只用 `##` 标题、列表、表格、粗体、链接：

1. **一句话结论**（不加标题，放最前面）：这周验证中的项目过没过它的指标；没有在验证的，就直说「这周没有在验证的项目」，并点名下周该验证哪一个。
2. `## 这周的验证`：项目名、`experiment_metric` 定的数、到今天的 `result`（没填就写「没有记结果」）、过没过，按 `stop_condition` 该继续、换渠道还是淘汰。到期（`due_at` 已过）没推进的单独列出来。
3. `## 池子这周的变化`：只列 `history` 里最近 7 天有变化的项目（谁从什么状态到什么状态，为什么），再一行写现在各状态各多少个。
4. `## 下周只做一个实验`：从「验证中」或排队的「待验证」里挑一个，写清第 1 步做什么、花多少钱、第 7 天看哪个数。只写一个。
5. `## 工具链还缺哪一环`：他的工具链是 找客户 / 抓数据 / 写内容 / 发布 / 收款客服 / 监控。看收藏和这周日报里的工具，哪一环还空着或最弱，下周日报的 GitHub 和 Skills 该往哪一环找。
6. `## 各主线和信源`：一张表，每条主线这周出了几个今日机会、几个进了池子；再一两句写 `metrics.json` 里哪个来源出了能进池子的机会，哪个来源 30 天都没出货（考虑删掉）。

## 红线

- 只写仓库里有的事实和数字，不编结果。没有数据的写「没有记录」。
- 不写空话，不重复日报原文。仓库是公开的，不写客户名字、邮箱、报价单。
- 只写 `data/weekly/<日期>.md` 这一个文件。
